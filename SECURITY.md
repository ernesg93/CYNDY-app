# Security Policy

## Supported versions

CYNDY is under active development and has no supported public release yet. This policy will be updated when the first version is published.

## Report a vulnerability

Use GitHub private vulnerability reporting after the public repository enables it. Until that channel exists, contact the repository owner privately through a trusted channel already known to you. Do not disclose vulnerability details in a public issue, discussion, pull request, or commit.

Include the affected area, reproduction steps, impact, and any suggested mitigation. Do not include real user data, live credentials, or unnecessary exploit data.

## Response expectations

The maintainer will acknowledge a report, assess severity, coordinate remediation, and agree on disclosure timing. Exact response-time commitments will be published when a staffed release process exists.

## Accidental secret exposure

Treat a committed secret as compromised even if it is later deleted. Stop distribution, rotate or revoke it at its provider, preserve only non-sensitive incident evidence, and remove the material from repository history before publication.
